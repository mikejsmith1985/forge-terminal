# v3.12.15 Updater Transition Fix

## Problem
The binary rename from `forge-windows-amd64.exe` → `fterm.exe` broke updates for existing users.

**Root Cause:**
- Old binaries (v3.12.14 and earlier) have old updater code
- Old updater looks for `forge-windows-amd64.exe` on GitHub
- GitHub release only had `fterm.exe`
- Result: "no binary available for windows/amd64" error

## Solution
Updated v3.12.15 to provide **both** binary names during transition:

### 1. Updated Updater Logic (`internal/updater/updater.go`)
```go
// getAssetNames returns a list of asset names to try, in priority order
func getAssetNames() []string {
    if runtime.GOOS == "windows" {
        // Try new name first, fallback to old name for backward compatibility
        return []string{"fterm.exe", "forge-windows-amd64.exe"}
    }
    return []string{fmt.Sprintf("forge-%s-%s", goos, arch)}
}
```

The updater now:
1. Tries `fterm.exe` first (new name)
2. Falls back to `forge-windows-amd64.exe` if not found (old name)
3. Uses whichever is available in the GitHub release

### 2. Updated Release Workflow (`.github/workflows/release.yml`)
```yaml
# Build BOTH names for transition period
GOOS=windows GOARCH=amd64 go build -ldflags "$LDFLAGS -H=windowsgui" -o bin/fterm.exe ./cmd/forge
# Duplicate as old name for backward compatibility
cp bin/fterm.exe bin/forge-windows-amd64.exe
```

Release now includes:
- ✅ `fterm.exe` (new name, 18.5 MB)
- ✅ `forge-windows-amd64.exe` (same binary, old name, 18.5 MB)

### 3. Updated Makefile
Local builds now create both names:
```makefile
build-windows: frontend-build
	GOOS=windows GOARCH=amd64 go build $(LDFLAGS_WIN) -o bin/fterm.exe ./cmd/forge
	cp bin/fterm.exe bin/forge-windows-amd64.exe
```

## Migration Path

### Old Users (forge-windows-amd64.exe)
1. Run current `forge-windows-amd64.exe` (any version)
2. Check for updates → finds v3.12.15
3. Downloads `forge-windows-amd64.exe` (contains new updater code)
4. Installs to their current location
5. **Next update:** New updater code tries `fterm.exe` first
6. All future updates work seamlessly

### New Users
1. Download `fterm.exe` from v3.12.15+
2. All updates work normally

## Timeline
- **v3.12.15 (current):** Provides both binary names, updater tries both
- **Future releases:** Continue providing both names for 2-3 releases
- **Later:** Can drop `forge-windows-amd64.exe` once user base transitions

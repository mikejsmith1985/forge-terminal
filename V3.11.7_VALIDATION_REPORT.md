### Issue #2: Windows .exe Not Launching

**Build Configuration Analysis:** ✅ **All Correct**

| Component | Status | Details |
|-----------|--------|---------|
| Windows Build Flag | ✅ | `GOOS=windows GOARCH=amd64` |
| GUI Mode | ✅ | `-H=windowsgui` (no console) |
| Strip Flags | ✅ | `-s -w` (reduce size, avoid AV) |
| Version Injection | ⚠️ Fixed | `-X internal/updater.Version` |
| Frontend Assets | ⚠️ | Must verify `cmd/forge/web/assets/*` |

**Potential Causes:**

1. **Missing Frontend Assets**
   - If `frontend build` fails, `embed.FS` will be empty
   - Results in 404 errors when accessing UI
   - **Verify:** Check that `cmd/forge/web/assets/` contains `index-*.js` and `index-*.css`

2. **Port Conflicts**
   - App tries ports in order: `3005 → 8333 → 8080 → 9000 → 3000 → 3333`
   - If all ports taken, app fails to start
   - **Check:** Run `netstat -ano | findstr "3005 8333 8080 9000 3000 3333"`

3. **Windows Defender / SmartScreen**
   - Unsigned .exe triggers SmartScreen warning
   - User must click "More info" → "Run anyway"
   - Antivirus may quarantine the .exe
   - **Solution:** Right-click .exe → Properties → Check "Unblock" → Apply

4. **ConPTY Support Missing**
   - Requires Windows 10 version 1809 (October 2018) or later
   - **Check:** Run `winver` to verify Windows version

5. **Firewall Blocking**
   - Windows Firewall may block localhost connections
   - **Check:** Windows Defender Firewall → Allow an app

**GitHub Actions Workflow:** ✅ **No Issues Detected**

**Q: Could the version mismatch cause command cards to fail?**  
A: Unlikely directly, but it could cause frontend caching issues or update check conflicts that prevent proper initialization.

**Q: Is the GitHub Actions workflow the problem?**  
A: No, the workflow configuration is correct. The issue was the hardcoded version in the source files.

**Q: Will rebuilding fix the .exe launch issue?**  
A: Yes, if the issue is version-related. If the .exe still doesn't launch after rebuild, check:
   - Frontend assets exist in `cmd/forge/web/assets/`
   - Windows version is 1809+
   - Firewall/antivirus not blocking
   - Ports not all in use

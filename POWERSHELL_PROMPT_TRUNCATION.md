# PowerShell Prompt Path Truncation

## Issue

New terminal tabs show **truncated paths** in PowerShell prompt:

```powershell
# What you see:
tswin\jira-html-parser>

# What you expect:
C:\ProjectsWin\jira-html-parser>
```

## Root Cause

This is **PowerShell's default behavior**, not a Forge bug.

PowerShell uses the built-in `prompt` function to generate the prompt string. The default `prompt` function is:

```powershell
function prompt {
    "PS $($executionContext.SessionState.Path.CurrentLocation)$('>' * ($nestedPromptLevel + 1)) "
}
```

However, if you have a **PowerShell profile** (`$PROFILE`), it likely customizes the prompt. Common customizations include:

1. **Oh My Posh**: Popular prompt customizer that truncates paths
2. **Posh-Git**: Git integration that modifies prompt
3. **Custom prompt functions**: User-defined in profile

### Why It Truncates

Path truncation happens because:

1. **Console width limits**: Long paths waste horizontal space
2. **Readability**: `...\folder` is easier to scan than full paths
3. **Performance**: Shorter prompts reduce terminal redraws

PowerShell (and most modern shells) automatically shorten paths when:
- Path is longer than ~50 characters
- Current directory is deep in folder hierarchy
- Profile has custom truncation logic

## How to Check Your Profile

```powershell
# Check if profile exists
Test-Path $PROFILE

# View profile content
notepad $PROFILE

# Or in PowerShell:
Get-Content $PROFILE
```

Common profile locations:
- **PowerShell 5**: `C:\Users\<username>\Documents\WindowsPowerShell\Microsoft.PowerShell_profile.ps1`
- **PowerShell 7+**: `C:\Users\<username>\Documents\PowerShell\Microsoft.PowerShell_profile.ps1`

## Solutions

### Option 1: Show Full Path (Simple)

Add this to your `$PROFILE`:

```powershell
function prompt {
    # Show full path with drive letter
    "PS $($PWD.Path)> "
}
```

**Result**: `PS C:\ProjectsWin\jira-html-parser> `

### Option 2: Show Full Path Without "PS" Prefix

```powershell
function prompt {
    "$($PWD.Path)> "
}
```

**Result**: `C:\ProjectsWin\jira-html-parser> `

### Option 3: Smart Truncation (Keep Last 2 Folders)

```powershell
function prompt {
    $pathParts = $PWD.Path.Split([IO.Path]::DirectorySeparatorChar)
    if ($pathParts.Length -gt 3) {
        $short = "...\" + ($pathParts[-2..-1] -join '\')
    } else {
        $short = $PWD.Path
    }
    "$short> "
}
```

**Result**: `...\jira-html-parser> ` (shows last 2 folders)

### Option 4: Show Drive + Last Folder

```powershell
function prompt {
    $drive = (Get-Location).Drive.Name
    $folder = Split-Path -Leaf (Get-Location).Path
    "${drive}:\...\${folder}> "
}
```

**Result**: `C:\...\jira-html-parser> `

### Option 5: Full Path in Window Title, Short in Prompt

```powershell
function prompt {
    # Set window title to full path
    $Host.UI.RawUI.WindowTitle = $PWD.Path
    
    # Show only current folder in prompt
    $folder = Split-Path -Leaf $PWD.Path
    "$folder> "
}
```

**Result**: 
- Prompt: `jira-html-parser> `
- Window title: `C:\ProjectsWin\jira-html-parser`

## Forge Cannot Override This

Forge **cannot** modify your PowerShell prompt because:

1. **Prompt is generated by PowerShell**, not Forge
2. Forge uses ConPTY (Windows Pseudo Console) which is a **pass-through**
3. ConPTY doesn't modify terminal output - it's byte-for-byte what PowerShell sends
4. PowerShell profile loads **before** Forge can inject any commands

### What Forge Can Control

Forge **does** set these environment variables (you can use them):

```powershell
$env:FORGE_INSTANCE_PID    # Forge process ID
$env:FORGE_INSTANCE_PORT   # Forge API port
$env:FORGE_TAB_ID          # Current terminal tab ID (if set)
```

You can use these in your prompt:

```powershell
function prompt {
    $forgeTab = if ($env:FORGE_TAB_ID) { "[$($env:FORGE_TAB_ID)] " } else { "" }
    "${forgeTab}$($PWD.Path)> "
}
```

**Result**: `[tab-2] C:\ProjectsWin\jira-html-parser> `

## Why This Happens on New Tabs

When you create a new terminal tab in Forge:

1. Forge spawns `powershell.exe` (or `pwsh.exe`)
2. PowerShell loads your `$PROFILE`
3. Your profile sets the `prompt` function
4. PowerShell uses that function for **every prompt**

If your profile has Oh My Posh or other prompt customizers, they apply their truncation logic.

## Debugging

To see what's setting your prompt:

```powershell
# View current prompt function
Get-Content function:\prompt

# Check if Oh My Posh is loaded
Get-Command oh-my-posh -ErrorAction SilentlyContinue

# Check if Posh-Git is loaded
Get-Module Posh-Git

# Temporarily use full path prompt (current session only)
function prompt { "$($PWD.Path)> " }
```

## Recommended Solution

**Option 5** (Full path in title, short in prompt) is the best of both worlds:
- Prompt stays clean and short
- Window title shows full path for reference
- Works well with Oh My Posh and other tools

Add this to your `$PROFILE`:

```powershell
# Full path in window title, current folder in prompt
function prompt {
    $Host.UI.RawUI.WindowTitle = "PowerShell - $($PWD.Path)"
    
    $folder = Split-Path -Leaf $PWD.Path
    if (-not $folder) { $folder = $PWD.Path }  # Handle root paths
    
    "PS $folder> "
}
```

## Summary

**This is not a Forge bug**. PowerShell's `prompt` function (controlled by your `$PROFILE`) determines how paths are displayed. Forge uses ConPTY which passes through PowerShell's output byte-for-byte without modification.

To fix: Edit your PowerShell profile (`$PROFILE`) and customize the `prompt` function as shown above.

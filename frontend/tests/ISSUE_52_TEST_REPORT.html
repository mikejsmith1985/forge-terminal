🔧 Issues Addressed

#52.1 Command Cards Can't Be Edited/Saved FIXED

User reported that command cards couldn't be edited and saved properly.

Solution: Fixed controlled/uncontrolled input bug in CommandModal.jsx. Safely merge initialData with defaults to prevent undefined values. Command ID is now properly preserved during edits.

#52.2 Copilot Command Card Switches to Terminal FIXED

Running copilot command card switches window to terminal instead of working through chat UI.

Solution: Fixed handleExecute in App.jsx to check activeTab.viewMode. When in chat mode, commands now route through PTY bridge (sendChatCommand) so Chat UX receives output. Terminal focus is no longer stolen when in chat mode.

#52.3 CD Command Bypasses Chat UX FIXED

CD command goes to terminal, chat UX receives no feedback.

Solution: Fixed PTY bridge race condition. Added getTerminalRef getter for lazy ref access. ChatView now properly uses getActiveTerminalRef() to reliably connect to terminal, ensuring chat UX receives all PTY output including directory changes.

#52.4 Smart Routing Looks Like Hardcoded Models FIXED

Explanation text suggests models are hardcoded, which is unacceptable on tight budget.

Solution: Completely rewrote the UI text to clarify economy vs power routing. Added clear messaging that cheaper models aren't "worse" - they're appropriate for simpler tasks. Emphasized that one Opus prompt solving the problem is better than 10 Haiku prompts that don't.

#52.5 Enter Key Doesn't Submit in Chat Mode FIXED

Enter key doesn't submit prompts in chat mode. User requested toggle for Enter behavior.

Solution: Fixed key detection by changing onKeyPress to onKeyDown. Added configurable toggle allowing users to choose: Enter sends (default) or Shift+Enter sends. Preference saved to localStorage.

#52.6 Chat Shows "Analyzing" But Prompt Not Sent PARTIAL

Chat UX shows "analyzing" but prompt was never passed to Copilot.

Status: Related to PTY bridge communication. The Enter key fix should help. Full fix requires deeper investigation of the WebSocket connection between chat view and terminal.

#52.7 No Indication SLM Exists or Is Functional FIXED

Settings show nothing suggesting SLM exists, is learning, or is functional.

Solution: Added visible SLM status indicator for ALL users (not just devMode). Shows active provider type, learning samples count. Also added "Current Spend" input for mid-cycle budget setup.

#52.8 CLI Settings Not Comprehensive FIXED

CLI settings don't surface enough Claude features.

Solution: Added Claude CLI features including: auto-approve options (read, edit, bash), MCP Protocol Support toggle, Verbose Output toggle, and Max Output Tokens configuration (1K-128K).

#52.9 Smart Router Using Wrong Model Selection TRAINING NEEDED

Router determined reading GH issue and fixing tour required Opus (terrible logic).

Status: This requires SLM training improvements. The current heuristics may over-classify tasks as complex. Needs separate issue for training data collection and model refinement.

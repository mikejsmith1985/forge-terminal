# Session Monitor Duration Fix - v3.11.7

**Date:** 2026-01-05 19:44 UTC  
**Status:** ✅ FIX APPLIED  
**Severity:** CRITICAL - Data loss, incorrect session analysis

---

## 🐛 The Bug

User reported debug session showing:
```
Duration: 0 seconds  ← WRONG
Keystrokes: 0
Clicks: 5  ← Events captured!

User Action Timeline:
[14.2s] CLICK: SPAN "Active 2h ago"   ← Timestamps are correct!
[17.1s] CLICK: BUTTON "View Logs (2)"
[20.2s] CLICK: SPAN "0 snapshots"
[21.1s] CLICK: SPAN "1 turns"
[34.1s] CLICK: SPAN "I'm Done"
```

**Problem:** Duration shows 0 seconds, but events span 34 seconds with correct timestamps.

---

## 🔍 Root Cause Analysis

### File: `frontend/src/components/FollowMeDebugger.jsx`

**Line 399 (BEFORE FIX):**
```javascript
const session = {
  id: 'debug-' + Date.now(),
  timestamp: new Date().toISOString(),
  duration: recordingDuration,  // ❌ BUG: Uses React state
  events: eventsRef.current,
  ...
};
```

### Why It Failed

1. **`recordingDuration` is React state** - Updated via `setInterval` every 1 second
2. **State updates can be missed** if:
   - Component unmounts (tab switches)
   - Interval doesn't fire (browser throttling)
   - Race condition during stop
3. **The truth is in `startTimeRef`** - Actual start timestamp stored as ref
4. **Event timestamps are calculated correctly** using `Date.now() - startTimeRef.current`

**Result:** Events have correct timestamps (14.2s, 17.1s, 34.1s) but session duration is 0.

---

## ✅ The Fix

### File: `frontend/src/components/FollowMeDebugger.jsx` - Lines 395-408

**BEFORE:**
```javascript
const summary = generateSummary();
const session = {
  id: 'debug-' + Date.now(),
  timestamp: new Date().toISOString(),
  duration: recordingDuration,  // ❌ Stale state value
  events: eventsRef.current,
  consoleLogs: consoleLogsRef.current,
  networkRequests: networkRequestsRef.current,
  hasVideo: !!videoBlob,
  summary,
};
```

**AFTER (v3.11.7):**
```javascript
const summary = generateSummary();

// FIX v3.11.7: Calculate actual duration from start time, not from state
// recordingDuration may be stale or not updated if interval missed ticks
const actualDuration = Math.floor((Date.now() - startTimeRef.current) / 1000);

const session = {
  id: 'debug-' + Date.now(),
  timestamp: new Date().toISOString(),
  duration: actualDuration,  // ✅ Calculated from source of truth
  events: eventsRef.current,
  consoleLogs: consoleLogsRef.current,
  networkRequests: networkRequestsRef.current,
  hasVideo: !!videoBlob,
  summary,
};
```

**Changes:**
- Added 3 lines before session object creation
- Calculate `actualDuration` from `startTimeRef.current` (same as event timestamps)
- Changed `duration: recordingDuration` → `duration: actualDuration`

### Test 2: Session Interruption
```javascript

startRecording();
await sleep(3000);

// Switch tabs (triggers localStorage save)
switchTab('Terminal');
await sleep(2000);

// Return to Debug tab (restores session)
switchTab('Debug');
continueRecording();
await sleep(2000);

// Stop - total should be ~7 seconds
stopRecording();
expect(session.duration).toBeGreaterThanOrEqual(6);
```

### Test 3: Event Timestamp Consistency
```javascript
// Events should use same time base as duration
const firstEventTime = session.events[0].timestamp / 1000;  // Convert ms to s
const lastEventTime = session.events[session.events.length - 1].timestamp / 1000;
const eventSpan = lastEventTime - firstEventTime;

expect(Math.abs(eventSpan - session.duration)).toBeLessThan(2);  // Within 2s
```

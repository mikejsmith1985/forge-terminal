🔧 Terminal Resize Fix - v3.17.5

Fixed terminal text cut-off when switching tabs using double RAF pattern

📋 Problem Report

User-Reported Issue

Scenario:

  1. Create first terminal tab → works perfectly
  2. Create second terminal tab → works perfectly
  3. Switch back to first tab → ❌ text appears cut off

Symptoms:

  • Terminal text shifted left
  • Left margin no longer visible
  • Appears as if entire terminal viewport moved horizontally
  • Happens consistently when switching back to previously-created tabs

🔍 Root Cause Analysis

The Race Condition

Terminals are hidden using display: none (CSS optimization from v3.16.14 ghost flash fix). When a tab becomes visible:

// CSS transition sequence: 1. React changes isVisible prop from false → true 2. CSS changes from "display: none" → "display: flex" 3. Browser needs to: - Apply CSS changes - Recalculate layout - Measure container dimensions 4. Terminal fit() called

Why setTimeout(50ms) Failed

  • Not layout-aware: Arbitrary 50ms might be too short or too long
  • Browser timing varies: Depends on CPU load, GPU, other animations
  • No guarantee: fit() might fire before layout stabilizes
  • Result: fit() measures wrong container width → calculates wrong column count → text cut off

❌ Before (v3.17.4)

useEffect(() => { if (isVisible) { // ❌ Arbitrary timing setTimeout(() => { fitAddonRef.current.fit(); }, 50); } }, [isVisible]);

Issues:

  • 50ms might be too short
  • Not synchronized with layout
  • Race condition with CSS

✅ After (v3.17.5)

useEffect(() => { if (isVisible) { // ✅ Wait for CSS paint requestAnimationFrame(() => { // ✅ Wait for layout requestAnimationFrame(() => { fitAddonRef.current.fit(); }); }); } }, [isVisible]);

Benefits:

  • Synchronized with browser paint
  • Guaranteed post-layout timing
  • No race conditions

✨ The Solution: Double RAF Pattern

Why Double requestAnimationFrame?

First RAF: Queues callback to run after current frame completes painting

  • CSS display: flex has been applied
  • Browser has painted the visible terminal container

Second RAF: Queues callback to run after next frame

  • Layout recalculation is complete
  • Container dimensions are stable and measurable
  • fit() can now accurately calculate columns/rows

Result: Terminal fits perfectly to container every time! 🎉

Technical Implementation

// frontend/src/components/ForgeTerminal.jsx (line 664-680) // v3.17.5: Use double RAF for reliable post-layout fit timing // Fixes text cut-off issue when switching back to tabs useEffect(() => { if (isVisible && fitAddonRef.current && xtermRef.current) { requestAnimationFrame(() => { requestAnimationFrame(() => { if (fitAddonRef.current && xtermRef.current) { // ✅ Guaranteed to run after layout stabilization fitAddonRef.current.fit(); // Critical fix: Re-focus after fit on visibility change queueMicrotask(() => { if (xtermRef.current) { xtermRef.current.focus(); } }); } }); }); } }, [isVisible]);

Why Not Other Solutions?

Alternative 1: visibility: hidden instead of display: none

  • ❌ Reverts v3.16.14 ghost flash fix
  • ❌ Terminal stays in layout flow (performance impact)
  • ❌ Doesn't solve the fundamental timing issue

Alternative 2: Increase setTimeout delay

  • ❌ Still not synchronized with browser layout
  • ❌ Might work on your machine, fail on slower systems
  • ❌ Adds unnecessary delay on fast systems

Our Solution: Double RAF ✅

  • ✅ Synchronized with browser paint pipeline
  • ✅ Works on all systems (fast or slow)
  • ✅ No fixed delays - runs as soon as layout is ready
  • ✅ Maintains v3.16.14 ghost flash fix
  • ✅ Zero performance impact

🎯 Summary

This fix resolves the terminal text cut-off issue by replacing an unreliable setTimeout(50ms) with a double requestAnimationFrame pattern that guarantees fit() runs after the browser has completed layout recalculation. This ensures accurate terminal dimensions and prevents the text from appearing cut off when switching between tabs.

Result: Seamless tab switching with perfect terminal rendering every time! 🚀

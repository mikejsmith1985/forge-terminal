# AM Monitor Fix Applied - v3.11.7

## ✅ ROOT CAUSE IDENTIFIED

**Bug:** AM Logger `amDir` field was empty in existing logger instances.

**Why:** When `GetLLMLogger()` found an existing logger, it returned it without checking if `amDir` was set. Old loggers created during development/testing had empty `amDir`, causing `saveConversation()` to skip with warning: "amDir is empty".

**Evidence:**
```
PS> Get-Content forge.exe | Select-String "saveConversation skipped"
[LLM Logger] ⚠️ saveConversation skipped: amDir is empty
```

## ✅ FIX APPLIED

**File:** `internal/am/llm_logger.go` lines 145-163

**Change:**
```go
// BEFORE (Bug):
if logger, exists := llmLoggers[tabID]; exists {
    llmLoggersMu.RUnlock()
    log.Printf("[LLM Logger] ✓ Found existing logger for tab %s", tabID)
    return logger  // ← Returns logger even if amDir is empty!
}

// AFTER (Fixed):
if logger, exists := llmLoggers[tabID]; exists {
    llmLoggersMu.RUnlock()
    
    // v3.11.7 FIX: If existing logger has empty amDir, update it
    logger.mu.Lock()
    if logger.amDir == "" && amDir != "" {
        log.Printf("[LLM Logger] ⚠️ Updating empty amDir for tab %s to: %s", tabID, amDir)
        logger.amDir = amDir
    }
    logger.mu.Unlock()
    
    log.Printf("[LLM Logger] ✓ Found existing logger for tab %s (amDir: %s)", tabID, logger.amDir)
    return logger  // ← Now amDir is guaranteed to be set!
}
```

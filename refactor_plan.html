🚨 Problem Statement

CRITICAL BUG: Previous implementation used PTY injection (termRef.write()), causing:
  • Command Cards Broken: Instructions appended to commands (e.g., copilot\n\nContext: don't break stuff)
  • Enter Key Malfunction: Each press appended text again instead of executing once
  • Architectural Flaw: Client-side PTY writes cannot distinguish between user input and LLM context

Key Design Principles

  • ✅ Zero PTY Pollution: Context NEVER reaches the shell input buffer
  • ✅ Server-Side Logic: Backend decides when to inject context (only for LLM commands)
  • ✅ Transparent to User: Terminal shows clean commands, context injected server-side
  • ✅ Command Detection: Pattern matching to identify LLM-bound vs shell-bound commands

Go Implementation:

type PersistentContext struct {
    Enabled bool   `json:"enabled"`
    Text    string `json:"text"`
}

type ContextManager struct {
    contexts map[string]*PersistentContext // tabID → context
    mu       sync.RWMutex
}

func (cm *ContextManager) SetContext(tabID string, ctx *PersistentContext) {
    cm.mu.Lock()
    defer cm.mu.Unlock()
    cm.contexts[tabID] = ctx
}

func (cm *ContextManager) GetContext(tabID string) *PersistentContext {
    cm.mu.RLock()
    defer cm.mu.RUnlock()
    return cm.contexts[tabID]
}

🔍 Command Detection Logic

PENDING

LLM Commands (Inject Context):

  • copilot ... - GitHub Copilot CLI
  • claude ... - Claude CLI
  • @<agent> ... - Subagent invocation
  • aider ... - Aider AI assistant

Shell Commands (Pass-Through):

  • ls, cd, git, npm, etc.
  • Command cards (already have explicit commands)
  • User terminal input

Implementation:

func isLLMCommand(cmd string) bool {
    trimmed := strings.TrimSpace(cmd)
    llmPrefixes := []string{"copilot", "claude", "@", "aider"}
    
    for _, prefix := range llmPrefixes {
        if strings.HasPrefix(trimmed, prefix) {
            return true
        }
    }
    return false
}

## 💡 PowerShell Terminal Injection - Technical Deep Dive

### The Challenge: Windows ConPTY Limitation

**Key Insight:** Windows ConPTY (Console Pseudo-Terminal) **CANNOT** set true environment variables in child processes like Unix PTY can.

### Why This Matters:
- **Unix/Linux:** When you spawn a child process, you can pass environment variables via `cmd.Env` and they become part of the child's process environment (accessible via `/proc/PID/environ`)
- **Windows ConPTY:** The `conpty.Start()` call only takes a command string - no way to inject environment variables into the process environment block

### The Workaround: Type Commands Into the Shell

Since we can't set process-level environment variables on Windows, Forge **types commands into the shell** to set shell-level variables:

```go
// internal/terminal/pty_windows.go lines 50-78
go func() {
    time.Sleep(100 * time.Millisecond)  // Wait for shell to start
    
    if strings.Contains(strings.ToLower(shell), "powershell") {
        // TYPE these commands into PowerShell as if user typed them:
        cpty.Write([]byte(fmt.Sprintf("$env:FORGE_INSTANCE_PID=%d\r", forgePID)))
        cpty.Write([]byte(fmt.Sprintf("$env:FORGE_INSTANCE_PORT=%d\r", forgePortNum)))
        
        if workingDir != "" {
            cpty.Write([]byte("Set-Location \"" + workingDir + "\"\r"))
        }
    } else if strings.Contains(strings.ToLower(shell), "bash") {
        cpty.Write([]byte(fmt.Sprintf("export FORGE_INSTANCE_PID=%d\r", forgePID)))
        cpty.Write([]byte(fmt.Sprintf("export FORGE_INSTANCE_PORT=%d\r", forgePortNum)))
    } else {  // CMD.exe
        cpty.Write([]byte(fmt.Sprintf("SET FORGE_INSTANCE_PID=%d\r", forgePID)))
        cpty.Write([]byte(fmt.Sprintf("SET FORGE_INSTANCE_PORT=%d\r", forgePortNum)))
    }
    
    // Send 'clear' to hide the setup commands from user
    cpty.Write([]byte("clear\r"))
}()
```

### What Actually Happens (Step-by-Step):

1. **User opens Forge Terminal** → Forge main process starts (PID: e.g., 24700, Port: 8333)

2. **User opens a new terminal tab** → Forge calls `startPTYWithShell("powershell.exe", ...)`

3. **ConPTY spawns PowerShell child process** → PowerShell window initializes

4. **100ms delay** → Wait for PowerShell prompt to appear

5. **Forge TYPES commands** (as if user typed them):
   ```powershell
   $env:FORGE_INSTANCE_PID=24700
   $env:FORGE_INSTANCE_PORT=8333
   Set-Location "C:\ProjectsWin\forge-terminal"
   clear
   ```

6. **User sees clean shell** → Setup commands hidden by `clear`

7. **Variables now accessible** → User can run `echo $env:FORGE_INSTANCE_PID` and see `24700`

### Limitations of This Approach:

| Issue | Impact | Mitigation |
|-------|--------|------------|
| **Not true process env** | Won't show in `Get-Process -Id $PID \| Select-Object -ExpandProperty Environment` | Use **port ownership** as primary check |
| **Race condition** | 100ms may not be enough on slow systems | Increased from 50ms to 100ms based on testing |
| **User can unset** | `Remove-Item Env:\FORGE_INSTANCE_PID` clears it | Safeguard falls back to **Layer 2 (port check)** |
| **Visible in history** | Commands appear in shell history | Acceptable tradeoff for reliability |
| **Shell-specific** | Must detect shell type and use correct syntax | Supports PowerShell, bash, zsh, cmd.exe |

**Limitation:** Shell-level, not process-level on Windows

## 🔐 Why "External PowerShell" is Actually PTY Simulation

**User's Question:** "What is the PowerShell terminal you're opening external to Forge?"

**Answer:** There is **no external PowerShell window**. It's all happening inside the ConPTY pseudo-terminal:

1. **User sees:** Forge's web-based terminal UI
2. **Under the hood:** ConPTY creates a hidden console buffer
3. **Forge writes to PTY:** `$env:FORGE_INSTANCE_PID=24700\r`
4. **PowerShell receives:** Same as if user typed it
5. **PowerShell executes:** Sets environment variable
6. **Forge writes:** `clear\r` to hide the command
7. **User sees:** Clean prompt, variables already set

**It's not "external" - it's "injected via terminal input simulation"**

This is why it's less reliable than true environment variables - it's a hack to work around Windows ConPTY limitations.

🔧 Persistent Instruction Injection - Manual Test Guide

📋 Problem Identified

Root Cause: The persistent instruction injection was completely unimplemented!

The IsLLMCommand() function and GetContext() method existed but were NEVER called. The comment in handler.go:1016 said "Context injection happens at LLM API level, NOT here" but there was NO code actually implementing it anywhere.

✅ Fix Applied

Implementation: Added PTY input interception in internal/terminal/handler.go

Location: Lines 1014-1043 (before session.Write(data))

Logic:
  1. Detect when user presses Enter (command submission)
  2. Check if command is an LLM tool (IsLLMCommand)
  3. Retrieve persistent context from ContextManager
  4. If enabled, append instruction text before sending to PTY

🧪 Manual Test Steps

1 Open Forge Terminal on port 9999
http://localhost:9999

Dev server should already be running.

2 Enable Persistent Instructions (Server-Side Config)

Run this PowerShell command to enable the feature:

$config = @{ enabled = $true template = "INJECTED_TEST_CONTEXT_12345" } | ConvertTo-Json Invoke-WebRequest -Uri "http://localhost:9999/api/persistent-instruction" ` -Method POST ` -Body $config ` -ContentType "application/json"

Expected response: {"status":"success"}

3 Verify Config Was Saved
Invoke-WebRequest -Uri "http://localhost:9999/api/persistent-instruction" -Method GET | Select-Object -ExpandProperty Content

Expected output:

{"enabled":true,"template":"INJECTED_TEST_CONTEXT_12345"}
4 Notify Frontend (WebSocket Config)

Open browser console in Forge Terminal (F12) and run:

// Get the WebSocket connection const ws = window.wsConnections?.values().next().value; // Send config to backend ws.send(JSON.stringify({ type: "PROMPT_INJECTION_CONFIG", enabled: true, instruction: "INJECTED_TEST_CONTEXT_12345" })); console.log("✅ Sent persistent instruction config to backend");
5 Test with GitHub Copilot CLI

In the Forge Terminal, run:

copilot this is a test prompt

Expected Behavior:

  • The backend should detect this is an LLM command (starts with "copilot")
  • It should append " INJECTED_TEST_CONTEXT_12345" before sending to PTY
  • GitHub Copilot should receive: "this is a test prompt INJECTED_TEST_CONTEXT_12345"
  • Copilot's response should acknowledge the injected context
6 Check Backend Logs

Look for this log line in the dev server output:

[ContextManager] Injecting persistent instruction for session tab-XXX: cmd=copilot this is a test...

This confirms the injection logic was triggered.

7 Verify Regular Commands Unchanged

Test that non-LLM commands are NOT modified:

dir Get-Date echo "test"

These should work normally without any injection.

🎯 Expected Results

✅ Success Criteria:

  • GitHub Copilot CLI receives the appended instruction
  • Copilot's response mentions "INJECTED_TEST_CONTEXT_12345"
  • Backend logs show "[ContextManager] Injecting persistent instruction"
  • Regular shell commands (dir, echo) work normally
  • Other LLM tools (gh copilot, claude, aider) also receive injection

⚠️ What Could Go Wrong:

  • No injection: Check if WebSocket config was sent correctly
  • Command not detected: Verify IsLLMCommand() logic
  • Empty instruction: Confirm API config shows "enabled":true

📊 Supported LLM Commands

The following command prefixes will trigger injection:

  • copilot - GitHub Copilot CLI
  • gh copilot - GitHub CLI copilot extension
  • claude - Claude CLI
  • aider - Aider AI assistant
  • @reviewer, @architect - Subagent invocations

🐛 Debugging

If injection doesn't work, check these in order:

  1. Verify backend logs show: [ContextManager] Context configured
  2. Run GET /api/persistent-instruction to confirm enabled=true
  3. Check WebSocket message was sent (browser console Network tab)
  4. Look for injection log: [ContextManager] Injecting persistent instruction
  5. Verify command starts with supported LLM prefix

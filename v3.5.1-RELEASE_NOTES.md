**Release Date:** December 29, 2025

## 🎯 Overview

Forge Terminal v3.5.1 transforms the Chat UI into a **persistent orchestration layer** powered by SQLite. The Chat interface is now the source of truth for all conversations, with Smart Routing seamlessly selecting the best AI model without user configuration.

The old "AI Provider Configuration" modal has been removed entirely. Budget setup is now integrated into Settings → Intelligence.

---

## 🚀 Major Features

### 1. SQLite Chat Persistence
**Problem Solved:** Chat history was lost when restarting. Context was always starting from zero.

**Solution:**
- All messages persist to `~/.forge/chat/chat.db` using SQLite
- Full-text search (FTS5) across entire conversation history
- 24-hour context window that new CLI sessions can reference
- Images stored with messages at `~/.forge/chat/images/`
- Pure-Go SQLite driver (modernc.org/sqlite) - **no CGO required on any platform**

**Real-World Benefit:** User can restart Forge, scroll back through entire history, search for past conversations, and new AI sessions have context of what was discussed recently.

### 2. Chat Bridge (AM → Chat Sync)
**Problem Solved:** Terminal and Chat UX were disconnected. Terminal conversations weren't visible in Chat.

**Solution:**
- Chat Bridge subscribes to AM EventBus
- LLM_START, LLM_TURN, LLM_END events automatically sync to Chat
- Workers are registered when conversations start
- Terminal output appears as Chat messages in real-time

**Real-World Benefit:** Whether user is in Terminal view or Chat view, they see the same conversation. No data loss. Complete unified history.

### 3. Full-Text Search
**Problem Solved:** No way to find past conversations or specific insights.

**Solution:**
- Click "Search" icon in Chat header
- Type to search across all messages
- Results auto-scroll and highlight
- Keyboard navigation (↑↓ Enter Esc)
- FTS5 indexing for instant results

**Real-World Benefit:** Find exactly the conversation or solution you need in seconds.

### 4. Smart Model Selection (Visible)
**Problem Solved:** User didn't know which AI was responding or why.

**Solution:**
- Before each response, shows "Analyzing complexity..."
- Displays complexity badge (1-10 scale, color-coded)
- Shows recommended model and task type
- Worker badge on response shows which model actually responded

**Real-World Benefit:** Full transparency into AI selection. User learns which models are being used based on task complexity.

### 5. Image Upload & Display
**Problem Solved:** No way to include screenshots or images in Chat context.

**Solution:**
- Drag & drop images into Chat
- Paste images from clipboard
- File picker button in input area
- Images stored and served from `~/.forge/chat/images/`
- Inline display in Chat history

**Real-World Benefit:** Can paste a screenshot of an error, and the Chat history includes it for context in future sessions.

### 6. Model Capabilities Database
**Problem Solved:** No way to understand which models are available or their strengths.

**Solution:**
- 16 models indexed with capability scores:
  - Copilot CLI: 13 models (Claude Opus/Sonnet/Haiku, GPT-5.1, etc.)
  - Claude CLI: 3 models (opus, sonnet, haiku)
- Capability matrix: reasoning, coding, speed, context window, cost
- Task type mapping (writing, coding, analysis, etc.)
- Smart Routing uses this to pick best model for the job

**Real-World Benefit:** System automatically picks the right tool for the job without user having to think about it.

## 📊 API Endpoints (NEW)

All endpoints tested and working:

```
GET  /api/chat/messages?limit=100        → Retrieve messages
POST /api/chat/messages                   → Add message
GET  /api/chat/search?q=query&limit=10   → Full-text search
GET  /api/chat/context?hours=24           → Get context for SLM
POST /api/chat/images                     → Upload image
GET  /api/chat/images/{filename}          → Serve image
GET  /api/chat/workers                    → List workers
POST /api/chat/workers                    → Register worker
WS   /api/chat/ws                         → Real-time sync
```

Example usage (tested):
```bash
# Search for past conversations about "debugging"
curl http://localhost:3005/api/chat/search?q=debugging

# Get 24-hour context for SLM
curl http://localhost:3005/api/chat/context?hours=24

# Upload image
curl -F "image=@screenshot.png" http://localhost:3005/api/chat/images
```

## 🔧 Architecture

### Backend (Go)
- **store.go** - SQLite schema, CRUD operations, FTS5 search, image storage
- **bridge.go** - AM event subscription and message conversion
- **models.go** - 16 AI models with capability scoring
- **handlers_chat_store.go** - HTTP handlers for all chat operations

### Frontend (React)
- **ChatView.jsx** - SQLite integration, WebSocket sync, image upload
- **ChatSearchOverlay.jsx** - Search UI with keyboard navigation
- **ChatSidebar.jsx** - Settings integration
- **useChatStore.js** - React hook for message state

### Removed Components
- **RouterConfigOverlay** - Old "AI Provider Configuration" modal (DELETED)
- Manual tier configuration (Standard/Advanced/Expert) - REMOVED
- API key entry UI - REMOVED (uses CLI auth instead)

## 🗄️ Data Storage

### SQLite Schema
```
messages (id, type, content, timestamp, workerId, workerName, metadata, replyTo)
messages_fts5 (virtual table for full-text search)
images (filename, content_hash, size, width, height, uploaded_at)
workers (id, name, type, status, tabId, createdAt, lastActive)
archives (old messages compressed, timestamp > 7 days)
```

### File Locations
- `~/.forge/chat/chat.db` - SQLite database (65KB initial size)
- `~/.forge/chat/images/` - Uploaded images
- `~/.forge/forge.log` - Server logs with Chat initialization

## 🔄 Migration Guide

### For Users
1. **First Launch:** Forge automatically creates `~/.forge/chat/chat.db`
2. **Budget Setup:** Go to Settings → Intelligence tab to set budget
3. **No Action Needed:** Existing terminal conversations are separate from Chat history

### For Developers
- No breaking API changes to CLI tools (Copilot, Claude)
- Chat API is new, no existing code needs updating
- AM system unchanged (EventBus additions are backward compatible)

## 🚀 What's Next (v3.6.0)

The foundation is now in place for:

1. **Multi-Agent Orchestration**
   - Chat can spawn multiple terminal workers
   - Coordinate responses across agents
   - Aggregate results back to Chat

2. **Workflow Integration**
   - Execute saved workflows through Chat
   - Pass outputs between workflow steps
   - Store workflow history in Chat

3. **Advanced Context**
   - Thread messages to target specific agents
   - Weighted context injection (recent = higher weight)
   - Automatic context summarization

## 📝 Known Limitations

- WebSocket sync requires browser tab to be open
- Large image uploads (>10MB) not yet optimized
- Archive compression (messages >7 days old) is v3.6.0 feature
- Multi-tab sync works but may have 1-2s latency
